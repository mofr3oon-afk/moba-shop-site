# نشر التغييرات الحساسة

لا تُشغّل تغييرات الإنتاج قبل موافقة المالك وبعد أخذ نسخة احتياطية وفحص السياسات الفعلية في مشروع Supabase الصحيح.

الطلبات الحالية والقديمة لا تُحذف. الطلبات الجديدة تستخدم raw_data الموجود بالفعل لمفتاح المتابعة والبيانات الداخلية. الطلبات القديمة تتابع عبر الدعم إلى أن يُصدر الأدمن مفتاحًا خاصًا.

الدفع المباشر يحتاج bucket خاصًا قبل نشر الكود، وإلا يرفض إنشاء الطلب بدل فقد صورة التحويل. حضّر bucket باسم order-receipts مع public=false وحد للحجم 3MB وأنواع image/jpeg,image/png,image/webp فقط؛ لا تضف سياسات anon أو روابط عامة. أضف ORDER_RECEIPTS_BUCKET=order-receipts في بيئة الاختبار ثم الإنتاج بعد الموافقة. راجع RLS وسياسات Storage الفعلية؛ تفعيل RLS وحده لا يحذف سياسات قديمة غير آمنة.

أضف ORDER_ACCESS_SECRET عشوائيًا قويًا (32 بايت أو أكثر) مستقلًا عن أسرار الأدمن، وADMIN_SESSION_SECRET قويًا. لا تغيّر الأسرار الحالية دون موافقة. فقد/تغيير ORDER_ACCESS_SECRET يغيّر هوية محاولات الإعادة؛ مفاتيح الطلبات المحفوظة سابقًا تظل صالحة مقابل hash داخل الطلب.

الشحن اليدوي اختيار لكل منتج من لوحة الإدارة: direct أو manual. الافتراضي direct للحفاظ على السلوك الحالي. لم تُضف أسعار QR أو Roblox وهمية، ولم يُفترض أسلوب شحنهما. فعّل manual للباقات الفعلية فقط بعد مراجعتها مع المالك. لا تُطلب كلمات مرور أو أكواد QR داخل الموقع.
